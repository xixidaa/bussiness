# 导入核对与存储保证

导入沿用 Excel/CSV 预校验。文件内同粒度、同日期/周期、同渠道的所有重复行标为异常，不自动选一行覆盖其他行。服务端也再次校验整批，发现文件重复直接拒绝。

`POST /api/receipts/import` 先提交 `{ rows, preview: true }`，返回按日期/周期与渠道核对的金额、人数、差额、冲突状态和 `previewToken`，不写入。确认时提交 `{ rows, previewToken, confirmed }`。同键金额、人数、备注和附件完全相同的记录跳过，避免重复导入。其他同键记录必须明确确认才替换；页面列出替换数量和差额。月汇总与同月日明细不能在同批导入，已有日明细时也不能导入对应月汇总。日明细覆盖现有月汇总统计口径须明确确认。

预览 token 绑定当前用户、导入内容和该用户现有台账快照，新增、修改、删除导致快照变化后返回 409，要求重新核对。日/月数据分别核对，金额差额总和不能当作去重后的经营金额。

D1 将快照修订号校验、删除和插入放在同一个 `db.batch` 事务中，触发器跟踪所有台账写入。读取后发生并发修改或批次任何写入失败都会整体回滚，避免部分写入和其他用户数据丢失。

Express / MongoDB 保持现有单机部署。台账修改共用进程序列锁，读取等待修改完成；整批先做模型与唯一键校验，然后只写变化的记录。普通批量写入失败时补偿恢复本批次。**这不是 MongoDB 多文档事务：进程崩溃、机器断电、补偿期间数据库持续不可用，以及多个 Express 进程并发写入时，无法保证事务原子性。**严格事务保证需要在后续部署中配置 MongoDB 副本集并使用数据库事务，本次没有擅自更改现有持久化或部署架构。

同日同渠道连续录入保留现有唯一汇总记录。新增接口只在 `appendToExisting: true`、`existingId` 和 `expectedUpdatedAt` 都匹配时累计本次金额与人数；旧快照返回 409。此操作不新增真实交易笔数。

隔离验证：`node --test tests/import-reconciliation.test.js` 使用内存 SQLite 事务测试 D1 行为和共享核对算法，不连接真实业务数据库。
