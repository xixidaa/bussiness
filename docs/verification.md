## 修改内容

1. **连续录入**：录入表单拆分为 `ReceiptEntryForm.vue`，提交读取当前字段快照；按用户持久化日期/周期、粒度、渠道和草稿。保存并继续仅清空已提交的金额、人数、备注和附件状态；普通保存后再次新建沿用选择。编辑不覆盖新建草稿，明确清空才重置。停用渠道不自动换成其他渠道，提交时提示主动选择。
2. **同周期继续补录**：保留既有周期/渠道唯一汇总键，显示原金额、本次金额和累计金额人数，确认后才累加；取消、过期确认或原记录删除均不写入。已有日明细覆盖的历史月汇总禁止新增/累计，避免保存后经营金额不可见。
3. **统计口径**：指标、趋势、渠道分析及导出统一范围/粒度/渠道；同渠道同月份日记录优先，月汇总不重复计入，日度不会将月汇总虚分到每天。本年指标明确标注独立年份与渠道。人数是录入值之和，不等于去重人数或交易笔数；平均每人收款替代客单价，人数为0时显示不可计算。快速切换日期、筛选、定位和用户时，旧请求不得覆盖新结果。
4. **图表与核查**：默认突出总额，提供同数量日历周期的上期和按需渠道曲线；没有上期或上期金额为0时显示“暂无可比数据”。渠道分析展示金额、占比、变化。图点与渠道按钮定位相同范围的原始台账。预期收款渠道由现有配置持久化，只有这些渠道会触发零收款提醒，并提供核查与补录。
5. **导入核对**：复用 Excel/CSV 预校验，文件内重复全部提示，完全重复的导入跳过；按日期/周期和渠道展示已有金额、导入金额、人数及差额。冲突需勾选并确认，核对快照失效时返回409；日/月汇总冲突整批拒绝。两套后端行为一致。
6. **移动端和登录**：375/390px保留完整录入、筛选、统计、编辑和导出能力，恢复顶部新建/刷新按钮，修复长文确认、分页和日期弹层，移除遮挡指标的冗余悬浮按钮。登录页不再公开默认管理员凭据或演示金额；空库不自动生成演示收款，初始化不会覆盖已有密码，两套后端只验证存储的密码哈希。
